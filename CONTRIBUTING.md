# Contributing to Zeara

Thank you for your interest in contributing to Zeara!

Zeara is an all-in-one fitness tracking platform built as a learning and development project. Contributions, suggestions, bug reports, and constructive feedback are welcome.

## 1. Before Contributing

Before starting work, contributors are encouraged to:

- Read the [Project Overview](docs/project-overview.md).
- Review the [Product Requirements Document](docs/PRD.md).
- Understand the [Design Brief](docs/design-brief.md).
- Review the [Sitemap & User Flow](docs/sitemap-user-flow.md).
- Check the [Technical Specification](docs/technical-specification.md).
- Review the [Development Roadmap](docs/roadmap.md).

## 2. Reporting Bugs

If you discover a bug:

1. Open a GitHub Issue.
2. Provide a clear and descriptive title.
3. Explain the steps required to reproduce the issue.
4. Describe the expected behavior.
5. Describe the actual behavior.
6. Include screenshots or additional information when relevant.

## 3. Suggesting Features

Feature suggestions are welcome.

When proposing a feature:

- Explain the problem it aims to solve.
- Describe the proposed functionality.
- Explain how it could benefit users.
- Consider whether it fits the current project scope.

Please open an Issue before starting significant new functionality.

## 4. Development Workflow

Contributors should follow this workflow:

1. Check existing GitHub Issues.
2. Discuss the proposed task when necessary.
3. Create a separate branch.
4. Implement the changes.
5. Test the implementation.
6. Submit a Pull Request.
7. Wait for review before merging.

## 5. Branch Naming

Use descriptive branch names.

Examples:

- `feature/authentication`
- `feature/dashboard`
- `feature/workout-planner`
- `feature/workout-logger`
- `fix/login-validation`
- `docs/update-readme`

## 6. Commit Message Convention

Use clear and descriptive commit messages.

Suggested prefixes:

| Prefix | Purpose |
|---|---|
| `feat:` | Add a new feature |
| `fix:` | Fix a bug |
| `docs:` | Update documentation |
| `style:` | Make formatting or styling changes |
| `refactor:` | Improve code structure |
| `test:` | Add or update tests |
| `chore:` | Perform maintenance tasks |

Examples:

- `feat: add workout dashboard`
- `fix: resolve login validation`
- `docs: update project overview`

## 7. Pull Request Guidelines

Before submitting a Pull Request:

- Ensure the changes match the intended task.
- Test the affected functionality.
- Provide a clear description of the changes.
- Reference the related GitHub Issue when applicable.
- Include screenshots for UI changes when useful.

Pull Requests should be reviewed before being merged into the main branch.

## 8. Code and Design Principles

Contributions should follow these principles:

- Keep code readable and maintainable.
- Use reusable components where appropriate.
- Avoid unnecessary duplication.
- Maintain consistency with the established design system.
- Prioritize usability and accessibility.
- Protect user data and application security.

## 9. Communication

Please keep discussions respectful, constructive, and focused on improving the project.

If you are unsure about an implementation or design decision, open an Issue to discuss it.

## 10. Project Scope

Contributions should align with Zeara's vision:

**PLAN. TRACK. ANALYZE.**

Large changes or features outside the current MVP scope should be discussed before implementation.

---

Thank you for helping improve Zeara!
